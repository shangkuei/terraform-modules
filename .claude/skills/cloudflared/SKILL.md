# cloudflared module

Creates a Cloudflare Zero Trust Tunnel with locally-managed configuration, ingress rules, DNS CNAME records, and exposes the tunnel token for `cloudflared` to authenticate with.

Source repo: `github.com/shangkuei/terraform-modules//cloudflared`. Pin via `?ref=<tag>` — the SKILL.md installed locally matches the tag the user pinned.

## Canonical block

```hcl
module "tunnel" {
  source = "git::https://github.com/shangkuei/terraform-modules.git//cloudflared?ref=v1.0.0"

  account_id  = var.cloudflare_account_id
  tunnel_name = "my-tunnel"

  ingress_rules = [
    {
      hostname = "app.example.com"
      service  = "http://app.default.svc.cluster.local:8080"
    },
  ]

  zone_id = var.cloudflare_zone_id
  dns_records = {
    "app" = { name = "app" }
  }
}
```

## Required inputs

- `account_id` — Cloudflare Account ID.
- `tunnel_name` — Tunnel display name.

## Common optional inputs

- `ingress_rules` (default `[]`) — list of `{ hostname, service, path?, origin_request? }`. Module appends the catch-all automatically; do **not** add an `http_status:404` rule yourself.
- `default_service` (default `"http_status:404"`) — catch-all for the implicit final rule.
- `zone_id` — required only if `dns_records` is set.
- `dns_records` (default `{}`) — `map(object({ name, proxied?=true, ttl?=1, comment? }))`. Created as CNAME → `<tunnel-id>.cfargotunnel.com`.
- `config_enabled` (default `true`) — set to `false` if you're managing ingress config elsewhere (the tunnel resource is still created).

## Key outputs

- `tunnel_token` (**sensitive**) — pass to `cloudflared tunnel run --token <token>`. Store in a Kubernetes Secret (typically SOPS-encrypted) or container env.
- `tunnel_id`, `tunnel_name`, `tunnel_cname` — for cross-referencing in other resources.
- `dns_records` — the created records, keyed the same as the input.

## Gotchas

- **Provider v5 only.** Resource names changed from v4 (`cloudflare_tunnel` →
  `cloudflare_zero_trust_tunnel_cloudflared`). If migrating, follow the `terraform state mv` / `terraform import`
  recipe in the module README's v4→v5 section — do not re-create the tunnel or you lose the tunnel ID and have
  to re-deploy cloudflared everywhere.
- **`tunnel_token` is sourced from a data source**, not the tunnel resource. That means it's read on every plan;
  if the Cloudflare API is unreachable, plans fail. Don't re-export the token through additional outputs
  without `sensitive = true`.
- **`config_enabled = false`** disconnects the ingress config from this module entirely — useful when the
  tunnel is shared across stacks, but you also lose the canonical-block guarantees about the catch-all rule.
  Manage it elsewhere fully, or not at all.
- **`zone_id` and `dns_records` are paired.** Setting `dns_records` without `zone_id` plans-applies but fails
  at apply time. Validate both are set together.
- **`tunnel_secret`** is generated by `random_password` with a `base64sha256` keeper. Don't rotate it casually
  — rotating regenerates the tunnel credentials and forces cloudflared re-auth everywhere.
